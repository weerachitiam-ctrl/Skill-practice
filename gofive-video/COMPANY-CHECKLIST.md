# เช็กลิสต์ก่อนย้ายงานไปแอคเคาต์บริษัท

เป้าหมาย: ก่อนสร้าง skill, agent และกฎของโปรเจกต์นี้ในแอคเคาต์บริษัท ให้เช็กก่อนว่าบริษัท **มีกฎอะไรเขียนไว้แล้ว** และ **อะไรยังไม่มี** จะได้ไม่สร้างซ้ำหรือขัดกับกฎเดิม

> ไฟล์นี้เขียนจากเซสชันของแอคเคาต์ส่วนตัว ผู้เขียนมองไม่เห็นข้อมูลในแอคเคาต์บริษัท
> ทุกช่อง "มีแล้วหรือยัง" ต้องไปเช็กจริงในแอคเคาต์บริษัท หรือถามผู้ดูแลระบบ (admin)

## คำศัพท์ที่ใช้ในไฟล์นี้

- **admin** (ผู้ดูแลระบบ): คนที่ตั้งค่าแอคเคาต์บริษัทให้ทุกคนใช้
- **CLAUDE.md**: ไฟล์คู่มือที่ Claude อ่านทุกครั้งที่เริ่มทำงานในโฟลเดอร์นั้น
- **skill**: ชุดคำสั่งสำเร็จรูปสำหรับงานหนึ่งอย่าง (เช่น เขียนสคริปต์)
- **subagent**: ผู้ช่วยแยกที่ทำงานเฉพาะทาง (เช่น ผู้ตรวจอิสระ)
- **hook**: คำสั่งที่ทำงานอัตโนมัติเมื่อเกิดเหตุการณ์ เช่น ตอน Claude ทำงานเสร็จ
- **permissions** (สิทธิ์): กฎว่า Claude ทำอะไรได้หรือต้องถามก่อน
- **repository** (ที่เก็บโปรเจกต์บน GitHub)

## ขั้นที่ 1: รู้ว่ากฎอยู่ได้ที่ไหนบ้าง

กฎและเครื่องมือของ Claude Code อยู่ได้หลายระดับ ระดับบนกว่ามักมีผลกับทุกคน

| ระดับ | ตัวอย่างที่เก็บ | ใครดูแล |
|-------|----------------|---------|
| บริษัททั้งองค์กร | การตั้งค่าที่ admin กำหนดให้ทุกคน (managed settings), skill หรือ plugin ที่ admin แจกให้, ตัวเชื่อมต่อ (connector) ที่เปิดไว้ | admin |
| โปรเจกต์ / ทีม | `CLAUDE.md`, `.claude/skills/`, `.claude/agents/`, `.claude/settings.json` ในที่เก็บโปรเจกต์ | เจ้าของโปรเจกต์ |
| ส่วนตัว | `~/.claude/CLAUDE.md`, `~/.claude/skills/`, `~/.claude/agents/` | แต่ละคน |
| ฝั่ง GitHub | กฎป้องกันสาขา (branch protection), สิทธิ์เข้าที่เก็บ | เจ้าของที่เก็บ |

ตำแหน่งไฟล์ตั้งค่าระดับบริษัทและชื่อเมนูในหน้าตั้งค่าอาจเปลี่ยนตามเวอร์ชัน ให้ยืนยันกับเอกสารทางการก่อน:
https://code.claude.com/docs/en/ (หัวข้อ memory, settings, sub-agents)

## ขั้นที่ 2: สำรวจ (ทำในแอคเคาต์บริษัท)

เปิด Claude Code ในโฟลเดอร์โปรเจกต์ของบริษัท แล้วพิมพ์ทีละข้อ

1. ```text
   ในโปรเจกต์นี้ คุณเห็น skill และ subagent อะไรบ้าง
   ```
2. ```text
   ตอนนี้มีไฟล์ CLAUDE.md หรือกฎอะไรที่คุณอ่านอยู่บ้าง สรุปเป็นรายการ บอกว่ามาจากไฟล์ไหน
   ```
3. ```text
   มีการตั้งค่าสิทธิ์ (permissions) หรือ hook อะไรที่ทำงานอยู่บ้าง บอกว่ามาจากไฟล์ไหน
   ```
4. ในเทอร์มินัล ดูว่ามีโฟลเดอร์เหล่านี้ไหม

   ```bash
   ls -a .claude .claude/skills .claude/agents
   ls CLAUDE.md
   ```
5. ถาม admin ว่ามี skill, plugin หรือตัวเชื่อมต่อที่แจกให้ทั้งบริษัทแล้วอะไรบ้าง
6. ถามเจ้าของที่เก็บ GitHub ว่ามีกฎป้องกันสาขาหรือกติกาการ commit และ push อะไรไหม

## ขั้นที่ 4: ตัดสินใจจากผลสำรวจ

- **มีแล้วในระดับบริษัท:** ใช้ของบริษัท ไม่สร้างซ้ำ ถ้าของเดิมขัดกับกฎทดลอง ให้ปรับกฎทดลองให้ตามบริษัท
- **ยังไม่มี:** เสนอ admin ให้ทำเป็นกฎระดับบริษัท ถ้าเป็นเรื่องเฉพาะโปรเจกต์ ให้ใส่ในที่เก็บของโปรเจกต์
- **มีบางส่วน หรือขัดกัน:** จดไว้ในช่อง "ทำอย่างไรต่อ" แล้วถามเจ้าของกฎก่อนแก้
- **ข้อมูลทดลอง:** กฎแบรนด์ในโปรเจกต์นี้เป็นของทดลอง (สี ฟอนต์ คำต้องห้าม) ต้องแทนด้วยข้อมูลแบรนด์จริงของบริษัทก่อนใช้

## ขั้นที่ 5: ย้ายและทดสอบ

1. คัดลอกเฉพาะส่วนที่ยังไม่มีไปวางในตำแหน่งที่เหมาะสม (ตามตารางขั้นที่ 1)
2. ทดสอบตามแผนใน `TEST-PLAN.md` (ข้อ 3, 4, 5) ในแอคเคาต์บริษัท
3. อย่าใส่ข้อมูลลับ (รหัสผ่าน คีย์ ข้อมูลลูกค้าจริง) ลงในไฟล์กฎหรือ skill ที่ commit ขึ้น GitHub

## สิ่งที่ผู้เขียนยืนยันไม่ได้

- ตอนนี้มีอะไรอยู่ในแอคเคาต์บริษัทบ้าง: ต้องเช็กในแอคเคาต์นั้นเอง
- ตำแหน่งไฟล์ตั้งค่าระดับบริษัทและชื่อเมนูล่าสุด: ยืนยันกับเอกสารทางการหรือ admin
- แหล่งที่มาของ hook ในข้อ 13: ยังไม่ทราบ ตั้งจากฝั่งสภาพแวดล้อมของเซสชันทดลอง ไม่ใช่ไฟล์ในโปรเจกต์นี้
